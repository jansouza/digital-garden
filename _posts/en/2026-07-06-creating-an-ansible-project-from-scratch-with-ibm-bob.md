Over the last few months I've been testing AI assistants for DevOps tasks,
and one of the experiences that caught my attention the most was using
**IBM Bob** to generate a complete Ansible project, from scratch, with just
two prompts. No ready-made template. No copying and pasting code from
somewhere else.

## The challenge

I wanted to automate a classic operations task: checking and freeing up
disk space, something every infrastructure team has had to do by hand on
some server at three in the morning.

The goal was an Ansible project with:

- A role for disk **verification** (`disk_verification`)
- A role for **filesystem cleanup** (`filesystem_cleanup`)
- Separate playbooks for verification and for remediation
- Support for Ubuntu, CentOS and RHEL
- *Dry-run* mode, safety checks and documentation

## The two-phase approach

What made the result interesting was IBM Bob's two-step workflow:

**1. Plan Mode** — before writing any code, Bob generated a detailed
implementation plan, following Ansible best practices (role structure,
separation of concerns, use of handlers and variables, etc.). That let me
review the approach before a single line of code existed.

**2. Code Mode** — with the plan validated, Bob implemented the complete
project, ready to run.

This "plan before you code" format is what gives you the confidence to use
AI in automations that touch real infrastructure: you can review the
reasoning before reviewing the code.

## Result

With two prompts, the project came out with:

- Organized, reusable roles
- Decoupled verification and remediation playbooks
- Multi-distro support (Ubuntu, CentOS, RHEL)
- Dry-run and safety checks before any destructive action
- Documentation of the project itself

The details are recorded in two links: the implementation plan generated by
Bob and the complete code published on GitHub.

- Implementation plan: [link](https://github.com/jansouza/ansible_disk_space/blob/main/docs/implementation_plan.md)
- Complete code on GitHub: [link](https://github.com/jansouza/ansible_disk_space)

## Why this matters

It's not about replacing the people who write Ansible every day — it's
about shrinking the distance between "we have a repetitive operational
task" and "we have a testable, documented automation ready for review".
Seeing an entire project come out of two prompts, with a reviewable plan
before the code, is a strong sign of where DevOps automation is heading.

For me, IBM Bob proved to be a real turning point in this process:
quality infrastructure automation, generated with minimal effort.
